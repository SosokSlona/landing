1. Исходная проблема и вызовы масштабирования

Рыночный анализ сотен площадок требует непрерывного извлечения данных в реальном времени. Ключевые сложности архитектуры:

  • Анти-фрод и динамическая блокировка IP: необходимость распределенной ротации пулов прокси с автоматическим анализом отпечатков TLS (ja3/ja4).
  • Сверхвысокая частота дубликатов: обновление сотен тысяч записей в традиционных РСУБД (Postgres/MySQL) вызывало блокировки таблиц при `ON CONFLICT DO UPDATE`.
  • Требование к моментальному алертингу: разница между появлением лота и отправкой пуша в Telegram должна составлять менее 2 секунд для сохранения финансовой выгоды.

3. Ключевые фрагменты архитектуры

DDL-структура схемы ClickHouse с ZSTD-сжатием

Использование движка `ReplacingMergeTree` с версионированием по таймстемпу позволяет автоматически отбрасывать устаревшие срезы цен без оверхеда на транзакции. 

CREATE TABLE market_items (
    item_id UUID,
    source_id LowCardinality(String),
    price Decimal(18, 4) CODEC(ZSTD(3)),
    market_score Float32 CODEC(ZSTD(1)),
    created_at DateTime CODEC(DoubleDelta, ZSTD),
    updated_at DateTime64(3) CODEC(DoubleDelta, ZSTD),
    payload String CODEC(ZSTD(6))
) ENGINE = ReplacingMergeTree(updated_at)
PRIMARY KEY (source_id, item_id)
ORDER BY (source_id, item_id, created_at);

Асинхронный батч-воркер на Python (uvloop + aiohttp)

Накопление объектов в буферном батче с тайм-аутом 500мс минимизирует количество транзакций к диску и обеспечивает throughput > 12,000 records/sec. 

import asyncio
import uvloop

async def flush_batch(queue: asyncio.Queue, ch_client):
    batch = []
    while True:
        try:
            item = await asyncio.wait_for(queue.get(), timeout=0.5)
            batch.append(item)
            if len(batch) >= 5000:
                await ch_client.insert("market_items", batch)
                batch.clear()
        except asyncio.TimeoutError:
            if batch:
                await ch_client.insert("market_items", batch)
                batch.clear()
