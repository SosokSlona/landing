1. Проблема: высокая нагрузка L1 и жесткие требования NDA

В B2B-секторе первая линия поддержки перегружена типовыми регламентными вопросами по закрытой API-документации, интеграциям и техническим инструкциям. Однако использование публичных API (OpenAI/Anthropic) категорически запрещено политикой безопасности и NDA:

  • Никакие исходные коды, логи и персональные данные клиентов не должны покидать защищенный контур.
  • Галлюцинации недопустимы: модель не имеет права «додумывать» технические параметры.
  • При низкой уверенности тикет должен мгновенно бесшовно эскалироваться на дежурного инженера L2 в CRM.

3. Гибридный поиск: почему только векторного поиска недостаточно

В технической документации точные совпадения (коды ошибок, названия методов API `api/v2/auth/token`) часто теряются в чисто семантических векторных эмбеддингах. Мы применили гибридный подход: объединение полнотекстового поиска (Full-Text TSVector) и векторного поиска по косинусному расстоянию (`pgvector` с индексом HNSW) с взвешенным Reciprocal Rank Fusion (RRF).

hybrid_vector_search.sql HNSW + Fulltext Hybrid 
WITH vector_matches AS (
    SELECT id, document_chunk, 1 - (embedding <=> :query_vector) AS sim_score
    FROM kb_embeddings
    ORDER BY embedding <=> :query_vector
    LIMIT 20
),
text_matches AS (
    SELECT id, document_chunk, ts_rank(tsv_content, plainto_tsquery('russian', :query_text)) AS text_score
    FROM kb_embeddings
    WHERE tsv_content @@ plainto_tsquery('russian', :query_text)
    LIMIT 20
)
SELECT COALESCE(v.id, t.id) AS chunk_id,
       COALESCE(v.document_chunk, t.document_chunk) AS chunk,
       (COALESCE(v.sim_score, 0) * 0.6 + COALESCE(t.text_score, 0) * 0.4) AS final_rank
FROM vector_matches v
FULL OUTER JOIN text_matches t ON v.id = t.id
ORDER BY final_rank DESC
LIMIT 5;

4. Guardrails и защита от галлюцинаций

Перед отправкой ответа клиенту система выполняет верификацию утверждений: каждое утверждение в ответе проверяется на строгое присутствие в извлеченных чанках базы знаний. Если сходство ниже порога 0.88, ответ маркируется как «неподтвержденный» и передается оператору в качестве подсказки (draft), исключая дезинформацию клиентов.
